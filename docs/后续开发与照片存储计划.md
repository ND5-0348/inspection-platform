# 抽样检测平台后续开发与照片存储计划

版本：1.0  
日期：2026-08-18  
适用范围：本机开发、微信小程序、抽样员网页端、管理后台，以及后续腾讯云或天翼云生产部署。

## 1. 建设目标与原则

平台应形成可复核的证据链：检测单、随机派单、三级随机抽样位置、现场签到、每个样品照片、位置水印、检测结论、审核记录和操作日志必须相互关联。生产架构不绑定某一云厂商，业务代码只依赖统一的 `StorageProvider` 和 `MapProvider` 接口。

关键原则：

1. 每个随机样品位置至少1张、最多5张照片；没有照片不能提交审核。
2. 照片与任务号、样品位置编号、拍摄人、拍摄时间、WGS84原始坐标和定位精度绑定。
3. 水印必须写入图片像素，不能只在页面上叠加文字。
4. 数据库只保存照片元数据和对象键，不把大图片直接存入MySQL。
5. 对象存储桶保持私有，查看照片必须经过身份鉴权或短时签名地址。
6. 原始证据不可被普通用户覆盖；修改检测结果不能替换历史照片。
7. 地图故障不能阻断现场拍照：解析地址失败时保留坐标，并回退到检测单收货地址。

## 2. 本轮已实现范围

### 2.1 抽样员网页端

- 每个“第几托盘—第几箱—第几件”独立显示拍照入口和已拍数量。
- 调用浏览器高精度定位，后端按配置调用高德或百度逆地理编码。
- 在浏览器Canvas中把任务号、样品编号、地址、WGS84坐标、精度和时间写入JPEG像素。
- 上传时同时保存水印文本、水印版本、地图来源和SHA-256。
- 每个样品最多5张；所有样品照片和检测结论齐全后才能提交审核。

### 2.2 微信小程序

- 使用相机拍摄，不从相册复用历史图片。
- 获取WGS84高精度定位，解析现场地址。
- 使用离屏Canvas生成带像素水印的JPEG后上传。
- 按样品显示照片数量及已上传照片预览。
- 与网页端使用相同接口、相同校验规则和同一数据库记录。

### 2.3 管理端与服务端

- 管理员审核区按样品编号展示照片缩略图、地址和照片总数。
- 新增样品照片专用接口，校验任务归属、任务状态、样品编号、水印文本和照片上限。
- 提交审核时服务端再次检查每一个随机样品是否至少有1张照片。
- MySQL证据表新增样品编号、坐标、精度、地址、坐标系、地图服务商、拍摄时间、水印文本和水印版本字段。

## 3. 地图服务接入方案

### 3.1 推荐选择

首选高德Web服务API，百度地图作为可切换备选。国内地址解析通常更适合国内地图服务，但最终选择应通过实际出差区域100个以上点位的准确率、响应时间、额度和合同价格对比确定。

系统保存WGS84原始坐标，不把供应商转换后的坐标作为唯一事实来源：

- 高德模式：WGS84/GPS先调用坐标转换，再调用逆地理编码。
- 百度模式：逆地理编码请求明确声明输入为WGS84。
- 无密钥或调用失败：保存WGS84坐标，地址回退为订单收货地址，地图来源记为 `ORDER_ADDRESS`。

配置仅位于API服务器：

```dotenv
MAP_PROVIDER=amap
AMAP_WEB_SERVICE_KEY=正式Web服务Key
BAIDU_MAP_AK=
```

不得把Web服务Key写进网页包或小程序代码。后端需增加60秒坐标网格缓存、超时、重试一次、调用量监控和异常告警。后期地图页面展示可以再使用小程序地图组件，但证据水印的地址必须由后端统一解析。

## 4. 照片对象与数据模型

每张照片至少保存以下元数据：

| 字段 | 用途 |
| --- | --- |
| evidence_id | 全局唯一证据编号 |
| task_id / sample_key | 关联任务及P托盘-B箱-I件 |
| storage_provider / bucket / object_key | 定位云端对象，避免保存永久URL |
| file_name / mime_type / file_size | 文件信息 |
| sha256 / etag | 完整性校验 |
| latitude / longitude / accuracy | WGS84原始定位与精度 |
| address / map_provider | 地址解析结果及来源 |
| captured_at / uploaded_at / uploaded_by | 拍摄、上传时间和人员 |
| watermark_text / watermark_version | 水印内容和算法版本 |
| status | UPLOADING、ACTIVE、QUARANTINED、DELETED |

建议对象键：

```text
evidence/{yyyy}/{mm}/{taskId}/{sampleKey}/{evidenceId}/watermarked.jpg
evidence-original/{yyyy}/{mm}/{taskId}/{sampleKey}/{evidenceId}/original.jpg
```

对象键不得包含手机号、客户名称或详细地址，防止日志和运维页面泄露个人信息。

## 5. 妥善保存照片的生产方案

### 5.1 存储分层

- 本机开发：`data/uploads`，仅用于功能测试，不作为正式归档。
- 集成测试：MinIO私有桶，用于验证S3适配器、签名地址和断点上传。
- 生产：腾讯云COS或天翼云ZOS私有桶；天翼云ZOS提供S3协议/API，可通过统一S3适配器接入。
- MySQL：仅存业务元数据、对象键、哈希和审计记录。

### 5.2 安全措施

1. 存储桶禁止公共读写，应用使用最小权限子账号；前端不持有永久访问密钥。
2. 上传接口限制JPEG/PNG/WebP，单张建议不超过15MB；校验文件头而非只看扩展名。
3. 上传后计算SHA-256并写入数据库；读取或迁移时重新计算并比对。
4. 开启服务端加密；高敏场景使用KMS托管密钥并制定密钥轮换流程。
5. 管理端预览使用5分钟以内的签名URL，或者继续通过鉴权API流式读取。
6. 上传文件先进入隔离前缀，完成格式校验、病毒扫描和水印核验后再标记为ACTIVE。
7. 所有查看、下载、导出、删除操作记录操作人、任务、证据ID、IP和时间。

### 5.3 原图与水印图

当前开发版在网页或小程序端生成水印图后上传。生产版应升级为“双文件证据”：

1. 客户端上传原图和声明的定位元数据。
2. 服务端校验登录人、任务、样品位置、拍摄时间窗口和定位精度。
3. 服务端使用受控图片处理程序再次生成标准水印图。
4. 原图进入只读私有前缀，水印图供日常审核；两者分别计算SHA-256并建立关联。
5. 报告引用水印图，同时保留原图用于争议复核。

这样可以降低客户端伪造水印或不同手机渲染差异的风险。服务端图片处理依赖可在网络恢复后安装Sharp，或使用云厂商受控图片处理能力；上线验收前必须完成。

### 5.4 备份、容灾和生命周期

- 主桶开启版本控制；如合规允许，启用保留策略/对象锁，防止误删和覆盖。
- 同区域使用多可用区存储；另做跨区域复制或每日增量备份，避免单区域故障。
- MySQL每天全量备份、每5至15分钟binlog增量归档；备份文件与照片桶分账号或分项目保存。
- 每月自动抽检不少于100个对象的SHA-256；每季度执行一次数据库与照片联合恢复演练。
- 建议热存储180天，之后转低频存储；保留期限先按企业档案制度设置为5年，若行业法规或合同要求更长则覆盖该默认值。
- 到期删除必须走“申请—审批—延迟删除—审计留痕”，数据库保留删除凭证，不允许前端直接删对象。

建议目标：RPO不超过15分钟，RTO不超过4小时。正式值需结合业务停机容忍度和预算确认。

## 6. 腾讯云与天翼云可迁移架构

应用层定义如下能力，不直接调用某个厂商SDK：

```text
StorageProvider
├── putObject(stream, metadata)
├── getObject(objectKey)
├── headObject(objectKey)
├── createSignedReadUrl(objectKey, expiresIn)
├── copyObject(sourceKey, targetKey)
└── verifyChecksum(objectKey, sha256)
```

实现分为：`LocalStorageProvider`、`TianyiZosS3Provider`、`TencentCosProvider`。照片表增加 `storage_provider`、`bucket` 和 `object_key`，因此切换云厂商不改业务编号和证据关系。

天翼云生产拓扑建议：

```text
HTTPS域名/WAF → 负载均衡 → 2台Linux应用节点 → 天翼云RDS MySQL
                                   ├→ 天翼云ZOS私有桶
                                   ├→ 日志与监控
                                   └→ KMS/密钥管理
```

应用节点运行Linux、Nginx、Node.js LTS；不建议为该项目选择Windows服务器。生产数据库优先使用云数据库，而不是把MySQL与应用放在同一台轻量服务器。

从本机或腾讯云迁移到天翼云的步骤：

1. 建立天翼云测试桶和最小权限账号，先通过S3兼容测试套件。
2. 统计源桶全部对象，导出对象键、大小、SHA-256和证据ID清单。
3. 后台批量复制，逐对象校验数量、大小和SHA-256；失败对象自动重试并生成差异报告。
4. 开启双写观察期，数据库仍指向原存储，确认新写入可在两个云读取。
5. 短时冻结证据上传，补齐增量，切换 `STORAGE_DRIVER` 和读取优先级。
6. 观察7至14天后再停止旧桶写入；旧桶至少保留一个完整备份周期，不立即删除。

## 7. 后续开发排期

### 第一阶段：本机功能闭环（1周）

- 完成逐样品拍照、水印、地址解析、管理员审核预览。
- 增加照片删除/补拍审批规则，避免抽样员自行覆盖证据。
- 补足文件类型、大小、数量和异常定位测试。
- 在微信开发者工具及至少2台安卓、1台iPhone真机测试相机、定位、离屏Canvas和弱网重试。

验收：所有样品缺照时禁止提交；水印肉眼可见；数据库元数据与图片一致；断网后不会产生半条记录。

### 第二阶段：证据安全与对象存储（1至2周）

- 抽取 `StorageProvider`，接入MinIO并实现私有访问。
- 实现临时对象、服务端标准水印、双文件、SHA-256复核、上传幂等和失败清理。
- 增加图片压缩策略、缩略图和移动网络断点/重试。
- 增加证据查看和下载审计。

验收：重传不会重复计数；篡改文件能被发现；任何永久公网URL均不可访问。

### 第三阶段：地图、身份和业务强化（1至2周）

- 申请高德/百度正式Key，建立点位准确率对照测试。
- 设置签到/拍照距离阈值，超阈值进入异常审批而非直接丢弃。
- 接入微信正式登录、手机号/工号绑定、令牌撤销和细粒度RBAC。
- 增加照片拍摄时间与服务器时间偏差检测、模拟定位风险标记。

### 第四阶段：天翼云预生产与上线（2周）

- 建立Linux、RDS MySQL、ZOS、域名、HTTPS、WAF、日志、监控和告警。
- 完成自动迁移、数据库备份、版本控制、跨区域备份和恢复演练。
- 压测并评估峰值上传、图片浏览、地图调用和月度存储成本。
- 完成安全测试、权限检查、隐私告知、用户验收、灰度发布和回滚演练。

## 8. 上线验收清单

- [ ] 每张照片可追溯到任务、样品、人员、时间和坐标。
- [ ] 水印已经写入像素，服务端能验证或重新生成。
- [ ] 地图Key不出现在网页包和小程序包。
- [ ] 存储桶无公共访问，应用账号只有必要权限。
- [ ] SHA-256抽检、版本控制、加密和备份已开启。
- [ ] 数据库恢复后能重新关联并读取全部照片。
- [ ] 微信真机弱网、拒绝定位、地图超时和重复上传均有明确处理。
- [ ] 腾讯云/天翼云切换演练有校验报告和回滚步骤。
- [ ] 隐私政策说明采集照片、定位的目的、范围、期限和用户权利。

## 9. 需要业务方确认的参数

1. 照片法定/合同保留期限：建议初始按5年配置，但应由质量与法务确认。
2. 每个样品的最低和最高照片数：当前为1至5张。
3. 可接受的定位精度与现场距离阈值，例如精度大于200米时是否必须说明。
4. 是否需要保存未加水印原图，以及哪些角色可申请查看。
5. 天翼云地域、等保等级、预算、RPO/RTO和是否必须跨区域容灾。
6. 最终地图供应商及每日调用量，以便申请正确配额。
